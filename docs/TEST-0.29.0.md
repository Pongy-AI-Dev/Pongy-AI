# Проверки Pongy AI 0.29.0

## Среда и результат

Подготовительная среда: Linux, Node 24.22.1, локальный Chromium через Playwright. На продуктивный Render этот код автоматически не развёртывался.

- `npm test`: **780/780**, без пропусков и падений
- `npm run check`: проверка структуры, JavaScript/JSON-синтаксиса, ссылок ресурсов, согласованности версий и поиск известных форм секретов
- `npm run check:release`: дополнительно контроль SHA-256 каждого файла выпуска по `MANIFEST.sha256`
- Браузерные проверки: **64 набора Chromium**, включая повторные прогоны исправленных наборов. Подробные результаты и история первого прогона — в `docs/test-results-0.29.0.json`
- Новая интеграционная проверка камеры/API/MCP/локальной расшифровки: **19 проверок**

Первый общий UI-прогон не был полностью зелёным: пять наборов потребовали разбора. Исправлены ожидания порядка кнопок, соответствия цвета маскота выбранной теме и видимых пунктов меню. Дополнительная проверка фактической видимости обнаружила настоящий конфликт CSS: скрытая кнопка камеры оставалась видимой вне режима маскота. Конфликт устранён отдельным правилом `[hidden]`; оба затронутых набора и новый набор камеры запущены повторно. Отчёт сохраняет исходные падения, а не выдаёт их за успешный первый прогон.

## Что проверялось дополнительно

- Выдача подписки будит авторизованный long-poll; событие попадает в уведомления, отметка прочтения сохраняется
- Права, события, настройки модели/мышления и флаг использования подключения переживают выход/вход и перезапуск процесса **с той же SQLite-базой**
- Старая запись настроек не затирает более новые модель/мышление; записи одного аккаунта сериализованы
- Выключенное подключение запрещает последующие чтения данных до обращения к провайдеру
- Команды навыков/плагинов требуют явного намерения и однозначного имени установленного расширения
- Исчерпание общего бюджета фоновых GET не превращает `/api/me` в ложный выход/состояние offline
- Камера не загружает кадры без вопроса; при вопросе JPEG реально проходит `/api/files` и попадает в payload vision-провайдера
- Камера не создаёт второй микрофон; закрытие останавливает video tracks и возвращает маскота на место
- На мобильном viewport элементы камеры и поля MCP не выходят за границы; JSON конфигурации скрыт, токен MCP замаскирован
- Локальный Vosk действительно расшифровывает WAV; обычное прикрепление аудио создаёт реальный текстовый файл расшифровки
- Android: статические проверки CAMERA, ограничения origin и запроса runtime-разрешений. Это не проверка собранного APK
- Отдельные регрессионные проверки подписок, уведомлений, настроек, расширений, голоса, восстановления ответа и публичных правовых страниц

## Что эти тесты НЕ доказывают

AI-ответы и Google OAuth в большинстве интеграционных тестов заменены управляемыми фикстурами; успешный тест не означает доступность настоящего провайдера, прохождение Google verification или качество ответов. Vosk и WAV в новом тесте реальные; камера/микрофон виртуальные. На тестовой записи заметны ошибки отдельных слов — безошибочное распознавание не заявляется.

Firefox/WebKit, физические камеры/torch, iPhone, Android APK и Windows MSI в этой среде не проверялись. Новая fake-device camera suite явно пропускается в не-Chromium движках. Новые APK/MSI не собраны. Непрерывный live-video AI, IoT «Умный дом» и устранение недоступности Render у операторов не реализованы этим выпуском.

Ни синтаксическая проверка, ни автотесты не являются гарантией отсутствия всех ошибок. Чек-лист после развёртывания и требования постоянного хранения — в `docs/PATCH-0.29.0.md`.
