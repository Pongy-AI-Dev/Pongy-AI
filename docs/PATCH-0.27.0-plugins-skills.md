# Pongy AI 0.27.0 — плагины, навыки, OAuth и голос

## Установка поверх последнего патча 0.26.1 orb-connections

1. Сохраните резервную копию сервера и БД. Распакуйте ZIP в корень репозитория с заменой перечисленных файлов.
2. Не удаляйте `.env`, DATA_DIR, БД, ключи, загрузки и собственные конфигурации. Патч их не содержит и не меняет. Старые документы, ZIP расширения и установщики сохранены.
3. На Render выполните обычный deploy. Для основных функций достаточно прежнего `npm ci` / `npm start`. Новая таблица `user_extensions` создаётся автоматически, существующие записи не стираются.
4. Обновите страницу. Версия сайта/сервера/нативных исходников — **0.27.0**. Опубликованные MSI/APK всё ещё **0.20.0**; они не переименованы и не пересобраны. ZIP Chrome/Edge собран из актуальных исходников расширения; права и ID не расширены.

## Плагины и навыки

Настройки → Плагины/Навыки, либо `+` в composer. `+` включает, `−` выключает, карточка открывает описание. Состояние хранится на сервере отдельно для аккаунта. Стандартные элементы изначально выключены, чтобы не менять поведение существующих диалогов неожиданно.

Три стандартных плагина: Проверка источников, Ясный текст, Приватный черновик. Три навыка: Погода, Новости, Документы. Включённые инструкции действительно передаются ИИ на сервере. Это настройки поведения, **не** установка исполняемых модулей и не выдача дополнительных прав. Приватный черновик — помощь модели, не гарантированный DLP-фильтр.

«Создать свой навык» открывает диалог справа (на узком экране — ниже списка). ИИ может спросить уточнение, затем предлагает название, описание, инструкцию и безопасную встроенную иконку. Навык не сохраняется молча: нажмите «Сохранить навык», затем включите его `+`. Для конструктора нужен настроенный ИИ; его запросы учитываются в квоте.

Для актуальной погоды/новостей нужны реальные доступные источники и работающие поисковые инструменты. Навык не создаёт данные из ничего. Модель должна уточнять регион/дату, ссылаться на прочитанные источники, отличать прогноз от наблюдений и сообщать об отсутствии данных. Документы ограничены реально поддерживаемыми, доступными и читаемыми вложениями; «любой тип» без исключений не обещается.

## OAuth: точные настройки для вашего Render

```
FRONTEND_URL=https://pongy-ai.devs.surf
PUBLIC_API_ORIGIN=https://pongy-server.onrender.com
```

GitHub: **отдельное OAuth App для Connections**, полная пара `CONNECTION_GITHUB_CLIENT_ID` и `CONNECTION_GITHUB_CLIENT_SECRET`. В настройках этого же приложения:

```
Homepage URL: https://pongy-ai.devs.surf
Authorization callback URL: https://pongy-server.onrender.com/api/connections/github/callback
```

Не используйте ID приложения с callback `/auth/github/callback` вместе с секретом другого приложения. Патч убирает автоматическую подстановку клиента обычного входа в Connections; изменить зарегистрированный Redirect URI в вашем GitHub автоматически невозможно.

Google: `CONNECTION_GOOGLE_CLIENT_ID` и `CONNECTION_GOOGLE_CLIENT_SECRET` от одного Web OAuth client. Добавьте **все три** Authorized redirect URIs:

```
https://pongy-server.onrender.com/api/connections/google-drive/callback
https://pongy-server.onrender.com/api/connections/gmail/callback
https://pongy-server.onrender.com/api/connections/google-calendar/callback
```

Для обычного входа Google прежний `/auth/google/callback` остаётся отдельным сценарием. Google unverified-app warning нельзя честно устранить правкой Pongy: настройте consent screen, testing/test users для разработки и пройдите требуемую проверку scopes для публичного выпуска. Не отключайте проверки безопасности.

Новый OAuth flow:
- авторизованный POST start создаёт одноразовое состояние, PKCE Google и секрет исходной вкладки;
- секрет сохраняется только в sessionStorage инициирующей вкладки, не попадает в URL провайдера;
- callback сервера возвращает код и state во fragment адреса сайта, не требует сессионной cookie в top-level callback;
- сайт сразу удаляет fragment и завершает обмен авторизованным POST с секретом вкладки;
- проверяются аккаунт, сервис, срок, секрет, одноразовость и CSRF origin; реальные access/refresh tokens остаются зашифрованными на сервере.

Начинайте и завершайте подключение в одной вкладке. При отключённом sessionStorage, смене аккаунта, просроченном состоянии или заблокированной **самой API-сессии** понадобится повторный вход. Новый flow убирает зависимость от callback-cookie, но не отменяет требование авторизации. Если браузер полностью блокирует сессии между двумя доменами, настройте собственный API-поддомен того же site или HTTPS reverse proxy; не отключайте cookie/CSRF-защиту.

## Квота

Free: **80** принятых сервером запросов в сутки UTC, общий счётчик аккаунта для чатов и ИИ-конструктора. В 00:00 UTC новый день. Серверные отказы до резервирования не списываются; уже начатые запросы учитываются, включая прерванные. Локальные действия вроде открытия формы напоминания без запроса к серверному ИИ в эту квоту не входят.

Шкала использует `dailyUsed / dailyLimit`, а не вычитание из 100. Обновление после запроса и при открытии раздела. На пределе появляется интерактивный переход к выбору оплаты. Реальная интеграция приёма платежей **по-прежнему не настроена**: патч не выдумывает успешную покупку. Активное серверное `subscription_until` либо личный API снимают Free-ограничение, но не ограничения безопасности и размера чата.

## Голос и фон

Маскот не ставит разговор на паузу только из-за `visibilitychange`. Ручная пауза по кругу, закрытие, смена аккаунта, подтверждение действий и ошибки микрофона по-прежнему останавливают запись. Браузер/ОС могут остановить микрофон или выгрузить вкладку; закрытый или выгруженный сайт не может гарантированно слушать. Фокусировка другой вкладки по зову требует установленного Chrome/Edge companion и разрешения пользователя.

В режиме маскота скрыты подсказка и строка reasoning/search/model. Composer остаётся исходным. Smart выключается только в запросах voice mode, установлен отдельный ограниченный бюджет ответа. Для OpenRouter запрашивается отключение reasoning; Gemini допускает лишь minimal thinking. Мгновенная обработка без сетевых задержек не гарантируется. Настройки обычного чата не перезаписываются.

## Настоящий локальный нейроголос Piper

Piper не является бесплатным публичным облачным API. Добавлена реальная интеграция **локального процесса на вашем сервере**, а не сторонний endpoint. Запись/текст не отправляются внешнему TTS-провайдеру. Веса не вложены в патч, установка необязательна.

В Render Node service при наличии Python/venv измените Build Command:

```
npm ci && sh services/piper/install.sh
```

Скрипт ставит отдельное Python venv, скачивает `ru_RU-denis-medium` и проверяет SHA-256 модели и JSON. Он печатает абсолютные значения для переменных **этого же** сервера:

```
PIPER_PYTHON=/opt/render/project/src/data/piper-venv/bin/python
PIPER_MODEL=/opt/render/project/src/data/piper-model/ru_RU-denis-medium.onnx
```

Используйте пути, напечатанные скриптом именно в вашей среде. Start Command остаётся `npm start`. После deploy в «Интерфейс → Конкретный голос» выберите **Piper · Денис (локальный нейроголос)** и нажмите «Прослушать». Сам по себе патч не переключает голос без вашего выбора. Без Python/модели эти переменные оставьте пустыми.

Для Piper нужен запас RAM/CPU. Прогретый процесс переиспользует загруженную модель между фразами, простаивающий освобождается через 5 минут; отмена прерывает текущий процесс. Первый запуск/холодный Render медленнее. **Бесплатный тариф Render может не вместить Node + модель; бесплатность движка не означает бесплатность хостинга.** Если Python отсутствует в выбранной среде, нужен образ/сервер с Python, а не подмена голоса названием.

Только русский Денис реализован как нейроголос в этом патче; для английского остаются реальные голоса устройства. Piper runtime 1.3.0 — GPL-3.0-or-later; при распространении соблюдайте его лицензию. Карточка Denis указывает CC0 для датасета; проверяйте условия модели отдельно. Ссылки и альтернативы: [FREE-VOICES.md](FREE-VOICES.md).

## Проверки

Новые проверки: серверное сохранение и изоляция расширений, применение инструкций, реальный ИИ-конструктор с уточнением и подтверждением, квота ровно 80/UTC/Plus, OAuth callback без cookie и защищённый finish, UI desktop/mobile, фон без принудительной паузы. Финальные результаты запуска перечислены в сообщении с ZIP; Firefox/WebKit не следует считать проверенными без их отдельного запуска.
