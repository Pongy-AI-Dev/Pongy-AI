# Восстановление подключения и продолжение ответов — 0.27.0

**Исходный патч поверх последнего `api-interface-hotfix` 0.27.0.** Не новый установщик и не полный проект. Домен не изменён. Старые Windows/Android пакеты не переименованы и не пересобраны.

## Ответы ИИ

- При обрыве потока после получения текста эта часть остаётся в сообщении. Переключение модели больше не стирает её ради повторной генерации с нуля.
- Под неполным ответом появляется блок **«Ответ прерван, продолжить?» → «Продолжить»**. Продолжение дописывается в тот же ответ; повторное нажатие во время генерации недоступно. Точная команда «продолжи»/«continue» для последнего прерванного ответа делает то же самое.
- В контекст действительно передаётся неполный ответ: раньше фильтр удалял его вместе с ошибочными сообщениями. Для очень большого ответа передаётся ограниченный хвост и последний исходный запрос; это не обещание неограниченного контекста или дословного восстановления неизвестной части.
- Точное совпадение начала нового фрагмента с концом полученного текста удаляется на границе (окно до 8192 символов, совпадения от 12 символов при ручном и от 16 при автоматическом продолжении). Короткая похожая буква или одиночная граница кодового блока не удаляется. Это не гарантия отсутствия смысловых повторов у любой модели.
- `finish_reason: length` по-прежнему запускает ограниченное автоматическое продолжение. При достижении предела возвращается честный статус обрыва, а не ложное «готово», в том числе для обычного текста. Бесконечных запросов нет.
- При ручном продолжении завершённые вызовы инструментов не переигрываются. Формирование файлов по итоговому коду выполняется только после завершения и проверки полного склеенного ответа. Незавершённые аргументы инструмента не исполняются; некорректные файлы не прикрепляются.
- При временном сбое без ответа доступна кнопка **«Повторить запрос»**. Она срабатывает только по нажатию. Блокировка безопасности не предлагает «Продолжить». Истёкшие/отклонённые ключи и квоты не обходятся повторными запросами.
- Состояние прерывания и код причины сохраняются в локальной и серверной истории. Ошибка при продолжении не удаляет исходный текст. Изменяющийся хвост ответа различает последовательные продолжения в защите от повторов.
- Ошибочный/незавершённый ответ возвращает зарезервированный лимит. Успешное ручное продолжение учитывается как обычный запрос с учётом размера контекста и результата. Флаг продолжения не отключает дневной лимит, авторизацию или безопасность.

## Подключение и загрузка

- Экран медленной загрузки не выдаёт ожидание за окончательный отказ. Показывается проверка сервера, доступность сервера либо невозможность подтвердить связь. Кнопка повторной загрузки и автоматическое закрытие после готовности интерфейса сохранены.
- Проверка startup-экрана — один публичный `GET /healthz` с пределом 90 секунд; без cookies. Никакие сообщения или платежи она не отправляет.
- Публичный экран восстановления делает до **3 GET-проверок**: 60/30/15 секунд с интервалами 5 секунд; затем останавливается и оставляет ручную кнопку. При подтверждённом `{"status":"ok"}` разрешена одна автоматическая перезагрузка за пять минут. Если sessionStorage недоступен, остаётся ручная кнопка, а не цикл перезагрузок.
- Ожидание навигации Service Worker и нативных оболочек увеличено с 20/30 до 120 секунд. Чтение конфигурации и проверка сохранённой сессии также получают до 120 секунд. Это помогает переждать холодный старт, но не создаёт доступ к заблокированному маршруту.
- Предупреждения различают сообщение браузера о сети и невозможность связаться с Pongy. Оценка `effectiveType` не называется измерением радиосигнала.
- Кеш Service Worker по-прежнему содержит только публичную страницу восстановления и её общие ресурсы. API, переписки, ключи, приватные страницы не добавляются в кеш. Cookies, IndexedDB, настройки и история не очищаются.

## Что патч не исправляет

`HTTP=000`, `TLS=0`, `ERR_CONNECTION_RESET`/таймаут до HTTPS могут означать проблему маршрута или фильтрации между конкретной сетью и Render. Код сайта не может исправить такой маршрут. Наличие рабочего ответа из одной страны/города не доказывает доступность из другой сети. Этот патч **не гарантирует работу без VPN** и не меняет настройки Render, DNS, домен или сертификат.

Проверка HTTPS не отключена, `unsafe-eval` не добавлен. Не устанавливайте неизвестные сертификаты и не отключайте защиту браузера. Платный тариф не является доказанным исправлением региональной недоступности.

## Применение

1. Сделайте резервную копию текущих исходников, базы и конфигурации окружения.
2. Распакуйте ZIP в корень проекта после `Pongy-AI-0.27.0-api-interface-hotfix`, заменив одноимённые файлы. Ничего из данных или секретов не удаляйте. Новых зависимостей и миграций БД нет.
3. Обновите **Node-сервер и публичные файлы**, выполните новый deploy. Для сервиса можно использовать `Health Check Path = /healthz`, если этот маршрут доступен в вашей конфигурации.
4. Перезагрузите страницу. Старые журналы GitHub не изменятся: нужен новый workflow. Новый кеш публичной страницы имеет отдельную ревизию.
5. Чтобы применить именно нативное ожидание 120 секунд, пересоберите Windows/Android оболочки и установите обновлённый пакет. Сам ZIP никуда как программу устанавливать не нужно. В него не включены готовые MSI/APK.
6. Выполните `npm test`, `npm run test:ui`, `npm run check:release`. Для UI в CI используются установленные Playwright браузеры; локальный путь Chromium задаётся через `CHROMIUM_PATH`, если нужен.

Доставка провайдера, сеть пользователя, боевой Render и нативные устройства не заменяются локальными тестами. Результаты фактически выполненных проверок — в `VALIDATION-0.27.0-network-recovery.md`.
