# Pongy AI 0.24.0 — Connections, восприятие и настройка зова

## Установка

Это дополнение поверх актуального проекта со всеми предыдущими патчами, включая `0.23.1-polish-wake`. Распакуйте ZIP в корень репозитория, сохранив пути и заменив одноимённые файлы. Старые документы в docs удалять не нужно. Не удаляйте .env, рабочую базу данных и загруженные файлы. Сделайте резервную копию базы и настроек перед обновлением.

Зависимости npm не добавлялись. Перезапустите сервер и обновите страницу с очисткой кэша (Ctrl+F5). При изменении настроек OAuth также перезапустите сервер. Новые таблицы подключений создаются автоматически в существующей SQLite-базе. Версия 0.24.0 — функциональное обновление (+0.1); отдельные исправления без новых возможностей получают +0.0.1.

Версии в исходниках Windows/Android обновлены, но готовые MSI/APK в этот патч НЕ входят. Существующие установщики не переименовывались и не выдаются за новую сборку. Для обновления устанавливаемого приложения нужна отдельная нативная сборка и проверка на целевой ОС.

## Add Connections

В меню «+» поля сообщения добавлена кнопка Add Connections. Окно открывается по центру поверх интерфейса, поддерживает телефон, светлую/тёмную тему и прокрутку. Реальный статус подключения приходит с сервера.

Доступные адаптеры:

- GitHub: список/поиск репозиториев, чтение текстового файла `owner/repository/path` до 100 КБ (вывод в ИИ ограничен). Папки и бинарные файлы не анализируются этим адаптером.
- Google Drive: поиск файлов по имени, метаданные, текстовый экспорт Google Docs/Slides; таблица — CSV первого листа, не вся книга. Бинарный документ нужно прикрепить в чат.
- Gmail: поиск/список писем и чтение plain-text части конкретного письма; без вложений и HTML-only тела.
- Google Calendar: ближайшие события основного календаря и чтение выбранного события.
- Slack: список публичных каналов и последние сообщения выбранного публичного канала. Личные сообщения, закрытые каналы, отправка сообщений и запись не поддерживаются.

Результаты ограничены по размеру: обычно до 10 элементов списка, Slack — до 20 сообщений. Полный архив аккаунта не загружается. Telegram/WhatsApp и другие сервисы без реализованной авторизации не показаны как якобы работающие подключения.

### GitHub без настройки OAuth-приложения

Откройте GitHub → «+», вставьте fine-grained personal access token в защищённое поле. Выдавайте доступ только к нужным репозиториям и `Contents: Read-only`. Сервер проверяет токен через API GitHub до сохранения. Не отправляйте токен в чат и не коммитьте его в репозиторий.

### Настройка OAuth владельцем сервера

Заполните только используемые параметры в рабочем `.env` (образец — `.env.example`):

```
CONNECTION_GOOGLE_CLIENT_ID=
CONNECTION_GOOGLE_CLIENT_SECRET=
CONNECTION_GITHUB_CLIENT_ID=
CONNECTION_GITHUB_CLIENT_SECRET=
CONNECTION_SLACK_CLIENT_ID=
CONNECTION_SLACK_CLIENT_SECRET=
```

Google может использовать существующие GOOGLE_CLIENT_ID/GOOGLE_CLIENT_SECRET. Для GitHub лучше отдельное OAuth App: callback подключения отличается от callback входа в Pongy. Зарегистрируйте точные redirect URI на публичном адресе API (`PUBLIC_API_ORIGIN`, иначе FRONTEND_URL):

```
https://YOUR-API-HOST/api/connections/github/callback
https://YOUR-API-HOST/api/connections/google-drive/callback
https://YOUR-API-HOST/api/connections/gmail/callback
https://YOUR-API-HOST/api/connections/google-calendar/callback
https://YOUR-API-HOST/api/connections/slack/callback
```

Замените YOUR-API-HOST на свой домен. При раздельных API/frontend это именно адрес API. Настройте HTTPS, корректные публичные URL и браузерную сессию. Авторизация доступна вошедшему пользователю и проверяет одноразовый state, аккаунт и браузерный nonce.

Разрешения Google: `drive.readonly`, `gmail.readonly`, `calendar.events.readonly` (полные OAuth URL стандартных scopes указаны в lib/connections.js). Включите соответствующие Google APIs и настройте consent screen/test users; для публичного запуска Google может требовать проверку приложения и дополнительные требования для чувствительных/ограниченных scopes. Slack использует user scopes `channels:read,channels:history`. GitHub OAuth использует `read:user repo`: само разрешение repo у GitHub широкое, хотя Pongy реализует только чтение. Для минимальных прав предпочтителен fine-grained token.

Без клиентских ключей интерфейс показывает «Требуется настройка сервера», а не фиктивное подключение. Живые OAuth-потоки с вашими аккаунтами не проверялись: ключи владельца не предоставлены.

### Хранение и приватность

Токены шифруются AES-256-GCM в серверной SQLite-базе, с привязкой к пользователю и сервису. Обеспечьте постоянный `SESSION_SECRET` и постоянный диск базы: смена секрета делает прежние токены нечитаемыми, а эфемерный диск теряет подключения. Это серверное хранение, не синхронизация через Firestore.

Токен не сохраняется в localStorage и не отправляется ИИ. По явному запросу с названием подключённого сервиса выбранные данные передаются настроенному AI-провайдеру. В таком ответе инструменты публичного поиска/веба/изображений отключаются, чтобы не выносить приватный текст в публичные поисковые запросы. Содержимое сервиса трактуется как недоверенные данные, не команды. Операции записи не реализованы.

«Отключить» удаляет ключ из Pongy и отменяет незавершённое подключение, но не отзывает разрешение у провайдера. Отозвать grant/токен можно отдельно в настройках сервиса. Используйте минимальные разрешения.

## Голосовой зов: обязательная настройка при плохом распознавании имени

На реальной локальной модели Vosk синтетическая WAV-фраза «Эй, Понги» распозналась как «эй подвиги». Простое расширение списка имён не исправляет произвольное акустическое распознавание и повышает ложные срабатывания. Добавлена подтверждаемая пользователем персональная фраза:

1. Настройки → Интерфейс → включить «Активация голосом».
2. Разрешить микрофон и дождаться загрузки локальной модели.
3. Нажать «Настроить зов» → начать настройку.
4. Один раз сказать «Эй, Понги» и сделать паузу.
5. Проверить услышанную фразу, нажать сохранение, закрыть окно и повторить зов.

Сохраняется только подтверждённый текст в этом браузере, отдельно для языка; аудио настройки не отправляется на сервер. Фраза должна быть различимой, из нескольких слов с обращением. Совпадение ищется в начале реплики, не внутри произвольного текста; оставшаяся команда сохраняется. Настройку можно сбросить. Выключение функции останавливает фоновое слушание. Для самой команды браузерный речевой движок по-прежнему может использовать свой сетевой сервис; офлайн-резерв сохранён.

Регрессия прогоняет синтетический WAV через настоящий Vosk/WASM без подставленного transcript: до настройки совпадения нет, после подтверждения той же расшифровки — есть. Это проверка конкретного синтетического примера и механизма настройки, НЕ гарантия точности на живом микрофоне/любом голосе. Это не новая обученная wake-word-модель уровня Алисы. Вкладка браузера не может гарантированно поднимать окно поверх всех приложений ОС; ограничения платформы сохранены.

## Работа ИИ

- Уточнены инструкции анализа фото: видимые предметы, признаки и неопределённость; не выдумывать точную модель, цену или личность. Нужен AI-провайдер с поддержкой изображений.
- Публичные каталоги маркетплейсов читаются существующим веб-инструментом; добавлено ограниченное извлечение Product/Offer из JSON-LD, включая цену, валюту, продавца и ссылку. Данные страницы не выдаются за подтверждённый остаток/цену оформления заказа. Защищённые, JS-only страницы или вход могут оставаться недоступны; обхода CAPTCHA/авторизации нет.
- Добавлены правила намеренной фонетической английской речи кириллицей и контекстного продолжения мемов; изолированное «Сикс» → «Севен», но не вместо арифметики/перевода. Нет заявления, что модель переобучена или знает все мемы 2026 года; актуальность неизвестного проверяется доступными источниками.
- Продуктовые сведения: создатель — российская компания Pongy AI Dev, главный разработчик — Иван Сергеев, первый выпуск — 2026. Права разработчика и механизм входа не менялись.
