# Pongy AI 0.23.0 — патч к исходникам 0.22.2

## Что это

Патч содержит только новые и изменённые файлы с путями относительно корня репозитория. Ничего удалять не нужно. Это обновление **исходного кода сайта и нативных клиентов**, а не готовые перевыпущенные MSI/APK. Не заменяйте старые установщики переименованными файлами: они не получат новые нативные функции.

## Установка

1. Сделайте резервную копию репозитория, `DATA_DIR`, базы данных и постоянных секретов. Не удаляйте `.env`, `data/secrets.json`, VAPID-ключи и Android-ключ подписи.
2. Распакуйте патч **в корень** Pongy-AI-main с заменой совпадающих файлов. Не создавайте дополнительную вложенную папку.
3. Выполните `npm ci` на сервере под поддерживаемой версией Node.js (>=22). Зависимость Nodemailer обновлена до 10.2.1; используется штатная сборка better-sqlite3.
4. Выполните `npm run check` и `npm test`. Для браузерных тестов установите браузеры Playwright (`npx playwright install chromium`) и выполните `npm run test:ui`. Локально можно задать `CHROMIUM_PATH`.
5. Перезапустите сервер и обновите вкладку. Убедитесь, что версии HTML, CSS и сервера — 0.23.0. Настройка цвета и всплывающих уведомлений хранится **на устройстве**, не переносится между аккаунтами/устройствами автоматически.

## Реализовано

- Получатель оценок сервиса: `pongy.suppot@gmail.com` — именно этот адрес, как в запросе. Серая кнопка «Позже» находится над «Отправить отзыв», закрывает окно без отправки. Очередь оценок сохраняется в БД, повторяется после временных сбоев; таймеры освобождаются при закрытии сервера.
- Шесть цветов интерфейса, обводка выбора, сохранение, штатный экран применения, согласованные оттенки светлой/тёмной темы. Ползунки навигации, переходы, раскрытие `details`, галочки, выровненные иконки и блоки файлов. Режим уменьшенных анимаций сохранён.
- Кнопка списка изменений справа сверху, **центрированное** окно, Plus под руководством/настройками, актуальная версия под полем ввода.
- «Активация голосом» перенесена только в «Интерфейс». Там же отдельный переключатель всплывающих сообщений сайта; он не выключает push, письма и центр уведомлений.
- API и API Key объединены под одним заголовком API, без удаления функциональности. Шкала диагностики скрыта до запуска; окно выбора проверки — в левом верхнем углу; вместо треугольных маркеров — единый шеврон.
- Новые названия чатов ограничены 30 Unicode-символами, включая многоточие. По возможности обрезаются по целым словам. Старые длинные названия отображаются сокращённо без массовой потери исходных данных.
- Обычное перетаскивание файлов использует тот же механизм загрузки, ограничения, отмену и прогресс, что и кнопка прикрепления. ZIP с исходниками и неподдерживаемыми бинарными файлами больше не отклоняется целиком: исключённые файлы явно перечисляются. Исходники не запускаются.
- Для пользовательских ссылок уточнены правила фактического чтения, доступен кэш страницы в рамках ответа и короткие plain-text страницы. HTTPS, SSRF/DNS/redirect-защита сохранены. Приватные, требующие входа и JavaScript страницы не обещаются как прочитанные. Улучшены указания по точным путям, частичному чтению и структуре блоков кода; это не обучение новой модели ИИ.

## Почта: что исправлено и что нужно настроить

Планировщик и почтовая очередь уже существовали. Теперь сервер передаёт общий настраиваемый SMTP-адаптер и в напоминания, добавлены проверка доставки на почту владельца аккаунта, отдельный статус канала и безопасные коды ошибок SMTP. Нельзя установить по архиву причину отказа **вашего** внешнего почтового сервера. Реальная доставка на Gmail из этого окружения не выполнялась.

Проверить на сервере:

- `MAIL_PROVIDER=smtp`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM`; либо `MAIL_PROVIDER=resend`, `RESEND_API_KEY`, `MAIL_FROM`.
- Gmail SMTP: обычно `smtp.gmail.com`, порт 465, `SMTP_SECURE=true`, пароль приложения Google, а не обычный пароль. `MAIL_FROM` должен соответствовать разрешённому отправителю.
- Resend: подтверждённый домен отправителя и разрешённый получатель. Проверить лимиты и панель доставки провайдера.
- Подтверждённая почта пользователя. Кнопка проверки отправляет письмо **только** на неё; переданный клиентом чужой адрес игнорируется. До трёх проверок в час на IP.
- Сервер должен работать в момент напоминания; БД и `DATA_DIR` должны быть постоянными, а не удаляемыми при redeploy. После настройки/смены почты нужен перезапуск процесса.
- В форме «Напоминание» нажмите «Проверить доставку на мою почту», проверьте входящие и спам. «Принято почтовым сервисом» не гарантирует попадание во входящие. Push и письма — независимые каналы.

## Разбор напоминаний

Текст, описание, дата, время, режим и количество сохраняются раздельно. Примеры:

- `Понги, напомни завтра в 18 позвонить маме`
- `Создай напоминание 27 октября в 7 вечера «Отправить отчёт», описание: приложить PDF`
- `Напомни в пятницу в 8 утра проверить почту`
- `Напомни каждый день в 18:00 пить воду 3 раза`

Используется часовой пояс устройства. Неуказанное время не подставляется как будто было распознано; окно просит его заполнить. Относительные секунды сохраняются через `dueAt`. Перед сохранением пользователь подтверждает форму. Неоднозначные/неподдержанные выражения и сложные повторения всё ещё могут потребовать ручной корректировки. В ежедневном режиме несколько повторов идут с существующим интервалом 5 минут, а не равномерно по суткам.

## Голос: реальные границы

- Имя обнаруживается локальной моделью Vosk. После имени сохраняется произнесённый фрагмент, запускается локальная диктовка, распознанная команда отправляется в чат. При 10 секундах тишины захват команды выключается; ожидание следующего имени включается снова, пока пользователь не выключил функцию.
- При выключении функции, выходе из аккаунта и занятом голосовом/ответном тракте микрофон освобождается. Автоввод не перезаписывает уже набранный черновик. Коды отказа разрешения не вызывают бесконечных запросов микрофона.
- Ждать имя совсем без микрофона невозможно. Это **не** системная служба Алисы и не копия её закрытого wake-word движка. Браузер может замораживать фоновую вкладку; закрытый сайт не слушает. По-прежнему нужны разрешение микрофона, модели и работающий аудиотракт.
- Обычному сайту браузер/ОС не гарантируют вывод вкладки поверх чужих окон. Для сайта используется уведомление, для нового Windows-клиента добавлена просьба ОС восстановить/активировать окно и сигнал панели задач. Windows тоже может ограничить кражу фокуса.
- Озвучка выбирает качественный доступный голос устройства; убрана искусственная смена высоты голоса, темп сглажен. Наличие нейроголоса зависит от ОС и браузера, новый платный TTS-провайдер не подключался.

## Windows и пересборка приложений — НЕ завершено выпуском

В `launcher.cpp` добавлен ограниченный мост WebView2: восстановление окна и открытие Блокнота, Калькулятора, Проводника. Мост проверяет origin, не принимает произвольные пути/аргументы, не выполняет shell/PowerShell; запуск требует подтверждения в интерфейсе и нативном окне. Полный контроль Windows, чтение всех файлов и управление любыми программами **не реализованы**. Файлы по-прежнему выбирает пользователь.

MSI/APK 0.23.0 **не собраны и не проверены установкой** в этом Linux-окружении. В патче нет новых установщиков. Для MSI нужны Windows/Visual Studio C++ либо MinGW, официальный WebView2 SDK и WiX. Для APK нужны Android SDK и **исходный ключ подписи**, которого нет в архиве. Не создавайте новый ключ взамен опубликованного.

Сборка на подготовленной машине:

```powershell
# Windows: запустить в корне репозитория; WEBVIEW2_SDK — официальный распакованный SDK
powershell -ExecutionPolicy Bypass -File native/windows/build.ps1
node scripts/register-native-release.cjs windows
```

```bash
# Android: ANDROID_HOME и PONGY_SIGNING_DIR должны указывать на SDK и исходную подпись
bash native/android/build.sh
node scripts/register-native-release.cjs android
```

После этого проверить подпись APK, установить оба приложения, проверить микрофон, диалоги, обновление поверх старой версии и работу в фоне. Скрипт регистрации обновляет размеры и SHA-256 **существующих собранных** пакетов в `public/downloads/releases.json`; не заменяет проверку подписи/поведения. До реальной сборки запись `files.*.version` остаётся 0.20.0 и ссылки указывают на настоящие старые файлы. Верхняя `version` — целевая версия исходников, не доказательство перевыпуска.

## Ограничения файлов

Существующий безопасный бюджет сохранён: ZIP/обычные файлы до 2 МБ, ZIP до 100 записей/8 МБ распакованного текста/2 МБ на запись. Изображения — до 25 МБ, видео — отдельный механизм. Пароли, симлинки и пути с выходом из архива запрещены. Вложенные ZIP и неподдержанные бинарники не анализируются. Скачиваемый `processed-*.zip` содержит только поддержанные неприватные файлы, **не является полной резервной копией** исходного архива. Частичное чтение отмечается явно.

## Правило версий

Используется `MAJOR.MINOR.PATCH`, а не десятичные дроби:

- новые заметные возможности: `0.22.2 → 0.23.0` (MINOR +1, PATCH = 0);
- совместимые исправления: `0.23.0 → 0.23.1` (PATCH +1);
- несовместимые публичные изменения после стабильного 1.0: MAJOR +1.

Обновлять согласованно package/lock, HTML/CSS/JS-маркеры, service worker, Android versionName + монотонный versionCode, Windows VersionInfo/WiX/build-пути. Исторические записи changelog не переписывать. Публичную запись о новом **установщике** менять только после реальной сборки и проверки.
