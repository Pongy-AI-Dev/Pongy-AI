# Pongy AI 0.26.1 — круг маскота, голоса и Connections

## Применение

Дополнительный ZIP поверх **0.26.1-voice-polish-hotfix**. Распакуйте с заменой одноимённых файлов в корень. Старые docs, реальные `.env`, базы, данные и загрузки не удалять. Обновите frontend и Render из одного коммита, перезагрузите сайт. Установщики и расширение не пересобраны; версия остаётся 0.26.1. Новых npm-зависимостей и платных API нет.

## Маскот и панель ввода

- Сам круг — доступная кнопка паузы/продолжения с клавиатурой, aria-label и состоянием aria-pressed. Отдельной кнопки «Пауза» больше нет. В паузе градиент красно-розовый, после продолжения — обычный. При незавершённом запросе/открытом подтверждении/черновике слушание не запускается преждевременно.
- Голосовой экран не создаёт DOM-узлы с текстом пользовательских и ИИ-реплик. Они продолжают отправляться/сохраняться в обычном чате, который закрыт голосовым экраном. Состояния «Слушаю», «Готовлю ответ», «Pongy отвечает» остаются. Настоящее состояние ошибок не скрывается.
- Переливы градиента, блики, объёмные тени, дыхание, волны и анимация ответа усилены. Двигается видимая поверхность, **не область нажатия**: круг остаётся удобно нажимаемым даже в паузе. Волны — анимация состояния, а не выдаваемая за измерение аудиограмма. Измеренный микрофон дополнительно влияет на масштаб. Reduced motion отключает движение.
- На мобильном поле имеет короткую подпись «Сообщение…» / “Message…”. Пустое поле не растягивается из-за переноса длинного placeholder. Введённый текст по-прежнему может быть многострочным.
- Меню «+» раскрывается с opacity/clip-анимацией, не сдвигающей координаты кнопок. Исправлено центрирование SVG-крестиков навыков, ответа и вложений; preview вложения сохраняет прежнюю flex-компоновку.
- Добавлен выбор конкретного предоставленного браузером голоса и прослушивание образца. [Подборка бесплатных голосов и реальные ограничения](FREE-VOICES.md).

## Connections

Отдельный раздел **Настройки → Подключения / Connections** показывает сервисы и открывает тот же OAuth-процесс, что «+ → Add Connections». Убраны рекламный eyebrow, повторяющиеся подписи и форма вставки токена. Пользователь выбирает сервис, нажимает «Подключить через …» и подтверждает доступ у провайдера. Секреты приложения задаёт владелец сайта один раз на сервере, не каждый пользователь. Существующие токены в базе и совместимый token API не удалены, но ручная форма не предлагается новым пользователям. Отключение по-прежнему требует подтверждения; приложение использует только операции чтения.

Google client ID/secret больше не смешиваются из разных OAuth-приложений при частично заданных CONNECTION-переменных. При отсутствии отдельной пары возможна полная пара обычного OAuth-клиента; для GitHub также доступна полная fallback-пара входа. **Callback Connections должен быть зарегистрирован у провайдера**; наличие клиента входа само по себе этого не гарантирует. GitHub OAuth repo scope шире read-only: разрешения показаны перед авторизацией; Pongy не выполняет записи.

## Почему был JSON «Войдите в аккаунт» на API-домене

Callback раньше проходил через обычный API auth и при отсутствии cookie отдавал JSON. Теперь отсутствие/истечение сессии на callback возвращает браузер на FRONTEND_URL с безопасным кодом ошибки; никакая услуга без действительной сессии не подключается. Пароли, authorization code и токены в frontend URL не попадают. Обычные API без сессии по-прежнему отвечают 401 JSON. State, браузерный nonce, PKCE, одноразовость и привязка к аккаунту не ослаблены.

Для разных HTTPS-хостов frontend и API default cookie становится SameSite=None; Secure сохраняется. Явный COOKIE_SAMESITE=lax не переопределяется. Cookie nonce Connections использует ту же политику вместо жёсткого lax. Это важно при старте через fetch с сайта на Render. Блокировка сторонних cookie самим браузером всё ещё может мешать: код не обходит её. Надёжный вариант — API на same-site домене или same-origin reverse proxy, настроенные владельцем. Браузерная панель «Автоформатировать» над JSON — не интерфейс Pongy; исправляется возврат на сайт, не скрытие панели браузера.

### Для текущего Render

```env
FRONTEND_URL=https://pongy-ai.devs.surf
PUBLIC_API_ORIGIN=https://pongy-server.onrender.com
COOKIE_SAMESITE=none
```

Если в Render уже стоит COOKIE_SAMESITE=lax, **замените его на none**. После redeploy выйдите и войдите снова, чтобы браузер получил новую cookie. Не публикуйте client secret и не вставляйте его в чат. Разрешения CORS/CSRF не расширены.

В Google Cloud для OAuth web client разрешите точные callback URI:

```text
https://pongy-server.onrender.com/api/connections/google-drive/callback
https://pongy-server.onrender.com/api/connections/gmail/callback
https://pongy-server.onrender.com/api/connections/google-calendar/callback
```

Обычный вход Google `/auth/google/callback` — отдельный маршрут. Включите Drive API, Gmail API, Calendar API и нужные readonly scopes в Google Auth Platform → Data Access. Для GitHub/Slack укажите соответствующий `/api/connections/github/callback` или `/api/connections/slack/callback`. Если клиент GitHub позволяет лишь один callback, используйте отдельное OAuth-приложение для Connections, а не ломайте существующий вход.

## «Google не проверил приложение»

Это проверка **проекта и OAuth scopes у Google**, не исправляемая скрытием текста, заменой кнопки или отключением state. Для тестирования добавьте свои аккаунты в Audience → Test users; тестовый режим не делает приложение проверенным и предупреждение может оставаться. Для публичного доступа заполните Branding, подтвердите домены/политику конфиденциальности и отправьте требуемые sensitive/restricted scopes на проверку. Gmail/Drive scopes могут требовать дополнительных проверок, включая security assessment по правилам Google. Простое переключение на Production не заменяет verification.

Источники: [Google: unverified apps](https://support.google.com/googleapi/answer/7454865?hl=en&ref_topic=7013279), [verification](https://support.google.com/cloud/answer/13463073?hl=en), [sensitive scopes](https://developers.google.com/identity/protocols/oauth2/production-readiness/sensitive-scope-verification). Утверждение, что патч «проверил приложение за Google», было бы неверным.
