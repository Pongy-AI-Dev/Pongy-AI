# Pongy AI 0.29.1 — установка и обязательные настройки

Версия повышена только на 0.0.1. Патч рассчитан на исходники 0.29.0. Для более ранней/неизвестной базы используйте полный снимок 0.29.1, не заменяя рабочие данные и секреты.

## 1. Установка

Сохраните исходники, всю SQLite-базу/каталог данных, переменные окружения и прежние ключи подписи приложений. Не публикуйте их в GitHub. Распакуйте патч в корень проекта с заменой файлов. Затем `npm ci`, `npm run check`, `npm test`, обычное развёртывание. Существующие домены и OAuth callback менять не требуется. Никакого автоматического деплоя из этой поставки не выполнялось.

## 2. Подписки вне диска Render — один раз настроить

Без следующей настройки сохранение по-прежнему зависит от SQLite. Наличие кода не означает, что внешний реестр уже подключён.

1. В том же проекте Google Cloud/Firebase, где находится Pongy, убедитесь, что создана Firestore Database `(default)`. Выберите подходящее для ваших юридических требований размещение данных. Услуга имеет квоты и собственные условия/стоимость; безлимитное бесплатное хранение не обещается.
2. Google Cloud → **IAM & Admin → Service Accounts → Create service account**. Создайте отдельный серверный аккаунт, например `pongy-subscriptions`. Выдайте роль **Cloud Datastore User** (`roles/datastore.user`). Это доступ сервера к данным Firestore, не роль посетителя сайта. Не выдавайте Owner и не используйте ключ в браузере. Оцените необходимые права/изоляцию проекта перед рабочим запуском.
3. Откройте созданный service account → **Keys → Add key → Create new key → JSON**. Храните файл у себя безопасно. Если организация запрещает создание ключей, не отключайте её политику: потребуется разрешённая администратором схема серверной аутентификации.
4. В Render → Environment добавьте **секретную** переменную `PONGY_PRODUCT_SERVICE_ACCOUNT_JSON`: полное содержимое JSON-файла. Не добавляйте её в репозиторий, клиентский Firebase config или переписку. Это не OAuth Client Secret и не публичный Firebase API Key: они не заменяют серверный service account. Не меняйте действующие `JWT_SECRET`/`SESSION_SECRET`.
5. Опубликуйте обновлённый `firestore.rules`: коллекция `pongyProductLedgerV1` должна быть закрыта для клиентских токенов. Сервер обращается с IAM service account. Запрещено открывать эту коллекцию правилом `allow read, write: if true`.
6. После запуска защищённый запрос владельца `GET /api/admin/product-storage` должен возвращать `mode: firestore-server`. Он показывает выбор режима, а не доказывает доступ к базе. Реальную запись подтвердит пробная выдача: она должна завершиться успешно, затем запись появится в Firestore.
7. Сохранность существующих прав: **до потери старого диска** сохраните согласованную копию исходной базы. На доверенной машине с этой базой, зависимостями проекта и серверной переменной выполните `node scripts/backup-products.js`. `DATABASE_PATH` должен указывать именно на исходную базу, не на пустой файл. Остановите процесс или используйте согласованную SQLite backup-операцию с учётом WAL/SHM. Дождитесь `Failed: 0`. Cloud-права при миграции авторитетны; ранее отозванная в облаке подписка не восстанавливается из старой копии.
8. Если база уже потеряна и облачной копии нет, восстановить неизвестные выдачи из ничего нельзя. Подтверждённые права придётся восстановить из своей резервной копии либо выдать заново владельцем после настройки внешнего реестра.

### Как работает защита

- Новая выдача/продление/отзыв подтверждается **после** успешной записи в Firestore. При сбое нет ложного сообщения об облачном сохранении.
- Обновление документа использует compare-and-swap. Одно событие оплаты повторно не продлевает срок; отзыв не отменяется правилом «выбрать больший срок».
- Права привязаны к подтверждённому адресу аккаунта, а не изменчивому локальному номеру пользователя. После создания новой SQLite и входа/подтверждения той же почты права восстанавливаются.
- Кэш подтверждения — до 10 секунд; обновления в одном процессе выдачи публикуются сразу. Несколько серверных экземпляров могут увидеть изменения с задержкой проверки. Нулевая задержка сети не гарантируется.
- Не подключённый режим сохраняет прежнее SQLite-поведение. Не используйте localStorage или пользовательские Firestore-документы как источник платных прав.
- Внешний реестр хранит подписки/ограниченную историю их событий. Он **не является резервной копией всего проекта**: OAuth-подключения, локальные аккаунты/пароли, заказы оплаты, файлы и ключи требуют своего постоянного хранения. Для Firebase-аккаунтов используйте существующую облачную историю; локальный аккаунт после потери базы может потребовать повторной регистрации/подтверждения почты.
- Для аккаунта хранятся последние 200 событий и до 5000 идентификаторов обработки. При исчерпании лимита новые выдачи завершаются ошибкой, а не обходят проверку: требуется администрируемое расширение реестра. Прочтение уведомлений при полной потере локальной базы отдельно не резервируется этим реестром.

## 3. Камера: последовательная передача кадров

Откройте маскота → `+` → «Камера». При открытой камере уменьшенные JPEG последовательно передаются на сервер примерно раз в две секунды (не чаще, с учётом сети). Один запрос в работе, тайм-аут восемь секунд, без бесконечной очереди. Для вопроса остаётся отдельный более чёткий текущий кадр; последние два серверных кадра добавляются для контекста движения.

Буфер только в RAM: до трёх кадров/сеанс, до двух активных сеансов/аккаунт, до 64 активных сеансов на процесс, срок до 10 секунд. Закрытие очищает буфер после доставки команды; при потере связи он истекает сам. Скрытие вкладки/смена аккаунта останавливают камеру. Другой аккаунт не может прочитать буфер. Кадры проверяются и перекодируются сервером, размер и частота ограничены.

Это **выборочная передача кадров**, не WebRTC 30 fps и не непрерывный realtime audio/video API модели. ИИ вызывается при вопросе, а не каждые две секунды. Точность анализа и задержка ответа зависят от vision-провайдера. Стоимость/квоты внешнего ИИ не снимаются. Поддержка аппаратной вспышки зависит от устройства.

## 4. «Умный дом»

Название раздела и иконка возвращены к «Умному дому». Внутри явно указано: доступен Windows-помощник «Умный ПК», оплата относится только к нему. Подключение реальных домашних устройств не изображается работающим. Для такой функции нужно выбрать интеграцию: Home Assistant, Matter либо API конкретного производителя, а затем безопасно связать устройства пользователя.

## 5. Обновления приложений

Исходники оболочек имеют версию 0.29.1; Android versionCode 291. Готовые APK/MSI в архиве остаются прежними 0.20.0, не переименованы. В подготовительной среде нет полного нативного toolchain и исходной подписи Android — новые установщики не собраны и на устройствах не проверены.

### Windows

GitHub → Actions → **Build Windows installer (manual)** → Run workflow. Исправлен реальный дефект: workflow искал файлы 0.27.0 при более новых исходниках. Теперь собирается и проверяется имя 0.29.1. Результат — unsigned MSI; доверенная подпись/проверка Windows отдельны.

### Android

В GitHub → Settings → Secrets and variables → Actions создайте:
- `PONGY_ANDROID_P12_BASE64` — base64 **исходного** `release.p12`
- `PONGY_ANDROID_STORE_PASSWORD` — пароль этой же исходной подписи

Затем Actions → **Build Android update (original signing identity)** → Run workflow. Скрипт сравнивает сертификат с опубликованным; несовпадение останавливает сборку. Ключ/пароль в артефакты не включаются. Если прежнего ключа нет, совместимое обновление установленного APK сделать нельзя: не подменяйте его новым ключом и не обходите проверку.

Успешный workflow нужно дополнить проверкой на устройстве и публикацией готового файла с верными version/bytes/SHA-256 в `public/downloads/releases.json`; до этого сайт продолжает честно предлагать прежний пакет. Автоматической публикации непроверенного APK/MSI нет.

## 6. Проверки после установки

- Выдайте пробную подписку, убедитесь в облачной записи и появлении доступа без перезагрузки. Сохраните копию, затем на отдельном тестовом экземпляре запустите пустую локальную базу и войдите с той же подтверждённой почтой. Доступ должен восстановиться.
- Отзовите доступ и повторите восстановление: старый срок не должен вернуться.
- Откройте камеру: виден статус передачи, кадры действительно идут в Network; без вопроса вызовов ИИ нет. Задайте вопрос о движении, закройте камеру, проверьте остановку запросов и индикатора захвата.
- Проверьте запрет камеры, слабую сеть, смену качества, камер и аккаунта, сворачивание/возврат. На реальных телефонах/собранных приложениях требуется отдельная проверка.

Автоматические результаты: `docs/TEST-0.29.1.md`. Этот патч не обещает мгновенную работу модели при недоступном провайдере, исправление всех багов или обход сетевой недоступности Render.
