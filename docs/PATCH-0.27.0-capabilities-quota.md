# Pongy AI 0.27.0 — навыки, квота, распознавание и отзывы

## Установка

Это **не полный проект**, а инкрементальный патч поверх актуальной 0.27.0 с `reliability-hotfix`. Распакуйте в корень репозитория с заменой файлов. Обновите **сервер Render и файлы сайта `public`**, затем перезагрузите открытые вкладки. Зависимости не менялись. Базу удалять не нужно: новые таблица резервов и поля очереди отзывов добавляются автоматически.

Версия исходников остаётся **0.27.0**: это исправление текущего выпуска, не новая сборка установщиков. Опубликованные MSI/APK 0.20.0 не пересобраны, не переименованы и не входят в архив.

## Навыки и плагины

- Перед отправкой фиксируется выбор для конкретного сообщения: один навык и до 12 плагинов. Сервер принимает только идентификаторы, сам загружает инструкции данного аккаунта и проверяет доступ. Клиентский текст инструкций не используется как полномочия.
- Выбор виден в поле ввода и отдельными компактными блоками рядом с отправленным сообщением. Блоки сохраняются в локальной и серверной истории. Их отключение не меняет подписи старых сообщений. Повтор/редактирование нового сообщения сохраняет его исходный выбор; если собственный навык был удалён, сервер откажет, а не подменит его другим.
- «Погода», «Новости» и «Проверка источников» получают доступ к необходимому публичному поиску/чтению даже без общего переключателя поиска. «Документы» и «Программист» получают релевантные доступные инструменты работы с файлами. Наличие навыка не гарантирует доступность внешнего источника или правильность ответа модели.
- Для собственных навыков/плагинов остаются ограничения длины, количества, безопасные иконки и изоляция аккаунтов. Это инструкции поведения, не произвольный исполняемый код и не новые разрешения. Они не могут обойти правила безопасности, включить платный сервис или открыть чужие данные. Встроенные сведения о личности Pongy не перезаписываются.
- Простые заготовленные разговорные ответы больше не обходят выбранный навык. Локальные действия сайта и формы напоминаний по-прежнему требуют подтверждения и не исполняют инструкции из навыка как команды.
- Ошибка загрузки выбора не отправляет запрос молча без навыка. Черновик сохраняется; подготовку можно отменить кнопкой остановки.

## Ресурсный лимит

Суточный Free-бюджет — **80 условных единиц, а не ровно 80 сообщений**. Начало суток — UTC. Это предсказуемая внутренняя оценка, **не счётчик оплаченных провайдеру токенов**.

Базовая стоимость: короткий запрос до 160 символов — 0,25; до 800 — 0,5; до 4 000 — 1; до 16 000 — 2; более длинный — 4. Распознаваемые запросы на разработку/отладку имеют минимум 1,5. Длинный передаваемый контекст и проверенные вложения увеличивают стоимость. После успешного ответа учитываются его длина и завершённые вызовы инструментов. Шаг — 0,25; верхняя граница одного запроса — 8 единиц. Общий расход никогда не превышает оставшийся суточный бюджет. Plus/собственный API сохраняют прежнее освобождение от Free-бюджета; это не означает бесплатность собственного внешнего API.

- Перед работой создаётся атомарный резерв. Техническая ошибка, пустой/оборванный ответ, отмена до завершения — возврат резерва. Ошибки валидации до резерва ничего не списывают. Повторные попытки провайдера внутри одного запроса не создают новые списания.
- Завершение и возврат идемпотентны. Незавершённые резервы восстанавливаются при старте сервера; завершённые не списываются повторно. Долгий активный запрос нельзя вытеснить конкурентным запросом, искусственно вернув его бюджет. Возврат относится к исходным суткам, в том числе после полуночи.
- Успешный ответ считается завершённым по серверному потоку, а не по флагам клиента. Если сервер завершил ответ, но клиент потерял уже доставленное соединение, автоматического доказательства неполучения нет.
- **Фактическую ошибку в формально успешном ответе нельзя надёжно распознать автоматически.** Такой ответ пока не получает автоматического возврата только по жалобе пользователя. Нельзя честно обещать обратное. Проверки не являются гарантией безошибочности модели.
- Ранее записанные дневные счётчики сохраняются как единицы; при обновлении они не обнуляются. Старые ошибки до патча задним числом не восстанавливаются, поскольку сервер не сохранял доказательство исхода каждого старого запроса.

Тот же расчёт применяется к чату, конструктору навыков и текстовым API/MCP-запросам. Пустой, ошибочный ответ конструктора или неразбираемый JSON без полей предложения/уточнения не расходуют бюджет. Локальное открытие формы напоминания без обращения к ИИ не расходует квоту модели.

## Доступность ИИ

Добавлен один ограниченный повтор последнего подходящего кандидата при временной сетевой/серверной ошибке или тайм-ауте начала ответа — только до выдачи текста и запуска инструментов, в пределах общего срока и числа попыток. Ошибки ключа, оплаты, политики и исчерпанной общей квоты так не маскируются. Никакого скрытого перехода на платные модели или чужого провайдера нет. Реальную перегрузку бесплатного API патч устранить не может.

## Распознавание и зов

В раздельном развёртывании сайт расположен на `https://pongy-ai.devs.surf`, а API — на `https://pongy-server.onrender.com`. Архивы моделей собирает API из частей. Поэтому загрузка `.tar.gz` со статического домена давала ошибку, хотя распознавание было в комплекте.

Теперь модель загружается с `PONGY_CONFIG.apiUrl`; при ошибке возможен один резервный переход к домену самой страницы. Worker остаётся на домене страницы; по сети скачиваются **файлы модели**, не записанный звук. Worker CSP разрешает только настроенный домен API для моделей. Главная страница не получает `unsafe-eval`. Поддержан также локальный тест с двумя loopback-портами.

Проверьте настройки:

```text
FRONTEND_URL=https://pongy-ai.devs.surf
PUBLIC_API_ORIGIN=https://pongy-server.onrender.com
```

На отдельном статическом сайте файл `public/app-config.js` должен задавать публичный адрес, **без секретов**:

```js
window.PONGY_CONFIG={apiUrl:'https://pongy-server.onrender.com'};
```

Патч не содержит этот файл с жёстко заданным доменом, чтобы не сломать локальный запуск и другие установки. При размещении всего сайта на одном сервере пустой `apiUrl` означает текущий домен и является нормой. Браузер должен разрешать соединение с API; в его CORS должен быть разрешён домен сайта.

При ошибке загрузки встроенного браузерного языкового пакета выполняется автоматический резервный запуск локального движка. При первом скачивании модели нужно дождаться готовности; объём — десятки МБ. Патч не превращает небольшую Vosk-модель в более точную большую модель: шум, язык и микрофон всё ещё влияют на распознавание.

Для зова удалены опасные встроенные совпадения с обычными именами/словами вроде «Ольге», «он ге». Их можно использовать только при явном персональном обучении. Частичное распознавание ждёт финального результата либо устойчивого текста и реальной тишины. Акустический шаблон сравнивается строже со всеми тремя образцами; слишком широкие старые пороги ограничены при проверке. Абсолютная защита от ложного срабатывания не обещается. Если старый образец перестал уверенно срабатывать, перезапишите один и тот же отчётливый зов три раза с паузами, в тихом месте.

## Почему отзывы могут не доходить

Сохранение отзыва, принятие письма провайдером и попадание во входящие — **разные этапы**. Теперь очередь хранит число попыток, время последней ошибки, безопасный код и время повторной попытки. Повтор использует прежний идентификатор письма; у Resend это также ключ идемпотентности. В интерфейсе сказано «Отзыв сохранён», а не что письмо уже доставлено. Веб-сайт не начинает показывать запрос оценки: правило «только приложения» сохранено.

Получатель по умолчанию остаётся прежним: `pongy.suppot@gmail.com`. **Проверьте написание и наличие доступа именно к этому ящику.** Если нужен другой адрес, задайте `FEEDBACK_EMAIL` в Render. Адрес не меняется самовольно.

На Render с заблокированным SMTP нужен разрешённый почтовый транспорт, например Resend **по HTTPS**, с рабочими настройками:

```text
MAIL_PROVIDER=resend
RESEND_API_KEY=<ключ, только в Render Environment>
MAIL_FROM=<разрешённый провайдером отправитель>
FEEDBACK_EMAIL=<ваш ящик для отзывов>
```

Не вставляйте ключ в `public/app-config.js`, GitHub или переписку. Если домен отправителя не подтверждён и провайдер не разрешает отправку, код не может обойти эту проверку. Тестовый отправитель Resend ограничивает получателей; он не заменяет настройку продакшен-почты. После изменения Environment перезапустите сервис. SQLite-очереди требуется постоянное хранилище: эфемерная файловая система Render может удалить её при перевыпуске сервиса; облачная история чатов сама по себе очередь отзывов не сохраняет.

Для уже существующего **серверно подтверждённого аккаунта разработчика** доступны авторизованные маршруты:

- `GET /api/admin/feedback-delivery` — настроен ли транспорт, провайдер, получатель, число ожидающих и принятых писем, код последней ошибки.
- `POST /api/admin/feedback-delivery/retry` с `{}` — повтор очереди после исправления настроек. Нужны текущая сессия и обычные разрешённые Origin/cookie. Endpoint ограничен по частоте. Не копируйте session cookie в чат.

Коды: `MAIL_AUTH_FAILED` — авторизация; `MAIL_SENDER_REJECTED` — отправитель/домен; `MAIL_CONNECTION_FAILED` — соединение/SMTP Render; `MAIL_RATE_LIMIT` — лимит провайдера. В журнал не выводятся сырой ответ провайдера, ключ или пароль. Статус `accepted` означает принятие провайдером, не гарантию попадания во входящие: также проверьте спам и журнал самого почтового провайдера.
