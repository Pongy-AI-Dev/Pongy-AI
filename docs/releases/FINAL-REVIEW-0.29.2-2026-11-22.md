# Pongy AI 0.29.2 — итоговая локальная проверка

Дата проверки: 22 ноября 2026 года
Среда: Windows x64, Node.js 24.19.0
Область: локальная рабочая копия и доступные автоматизированные проверки. Публикация, Git push и production deployment не выполнялись.

## 1. Исправление зависимостей

Первичный `npm audit --omit=dev` выявил две умеренные уязвимости в транзитивных зависимостях MCP SDK:

- `@hono/node-server`: 2.1.5 → 2.1.11;
- `hono`: 4.13.13 → 4.13.20.

Также обнаружено несоответствие старого lock-файла текущему `package.json`: lock-файл содержал версию проекта 0.29.1 и `better-sqlite3` 12.11.1, тогда как манифест проекта уже требовал 0.29.2 и `better-sqlite3` ^13.0.3. Lock-файл согласован с манифестом; установлен `better-sqlite3` 13.0.3.

После обновления и восстановления dev-зависимостей:

- `npm audit`: 0 уязвимостей (production и development зависимости);
- `npm ls`: версии Hono, MCP SDK и Playwright соответствуют ожидаемому дереву;
- Playwright 1.64.0 восстановлен для браузерной регрессии.

Обновление зависимостей прошло без принудительного major-upgrade Hono.

## 3. Статический аудит исходного кода

Повторный аудит охватил 381 исходный файл:

- 185 сигналов уровня `review`;
- 7 сигналов уровня `info`;
- 0 сигналов уровня `high` и `error`.

Групповая классификация сигналов:

| Категория | Всего | В тестах | В рабочем коде |
|---|---:|---:|---:|
| Присваивания HTML DOM-свойствам | 111 | 5 | 106 |
| Возможные строки учётных данных | 55 | 55 | 0 |
| Запуск процессов | 15 | 9 | 6 |
| Динамическое исполнение кода | 3 | 3 | 0 |
| Неразрешённые локальные импорты | 7 | 7 | 0 |
| `document.write` | 1 | 0 | 1 |

Интерпретация:

- 55 совпадений, похожих на учётные данные, находятся только в тестовых файлах; значения аудитор не выводит.
- Все 3 сигнала динамического исполнения и 7 сигналов локальных импортов относятся к тестовому коду.
- Шесть сигналов запуска процессов в рабочем коде относятся к ограниченным локальным операциям. Проверены фиксированные аргументы, отсутствие shell там, где он не требуется, и подтверждение пользователя перед запуском тестов выбранного проекта в PongX.
- Единственный `document.write` находится в изолированном preview-runner. Для него установлены CSP-ограничения, sandbox без same-origin и запрет сетевых соединений.
- HTML-сигналы требуют контекстного анализа: центральный Markdown renderer очищает разметку через DOMPurify; для Notes есть отдельные тесты очистки HTML, URL и CSS. Само совпадение с `innerHTML` не доказывает уязвимость.

Эти 185 сигналов не являются 185 подтверждёнными уязвимостями. Они оставлены в отчёте, а не скрыты изменением эвристик. Статический аудит не заменяет полноценный penetration test и ручной аудит каждой точки вывода.
