# Pongy AI — технический аудит исходного кода

## Назначение

Добавлен отдельный статический аудитор исходного кода. Он дополняет многоагентную проверку ответа и не подменяет компилятор, тестовый стенд, SAST-платформу или ручной аудит безопасности.

## Состав

- `lib/code-auditor.js` — общий ограниченный анализатор исходных файлов.
- `scripts/audit-project.cjs` — аудит рабочей копии репозитория.
- `audit:project` и `audit:project:json` — команды запуска.
- Инструмент `audit_project` — анализ читаемых файлов, прикреплённых к текущему чату/проекту.
- `check_code` и подготовка сгенерированных файлов дополнены статическими сигналами аудита.
- Журнал действий отображает этап аудита и ограниченный перечень замечаний; сведения сохраняются в локальной истории.

## Проверяемые сигналы

1. Возможные секреты и приватные environment-файлы. Значения секретов никогда не включаются в отчёт.
2. Использование динамического исполнения кода.
3. Вызовы запуска процессов.
4. Присваивания `innerHTML` / `outerHTML` и `document.write`.
5. Возможные отсутствующие относительные импорты в переданном наборе файлов.
6. Корректность JSON и безопасность относительных путей.

Уровни `high` и `error` требуют устранения или отдельного подтверждения перед автоматической упаковкой сгенерированных файлов. Уровень `review` — сигнал для анализа контекста, а `info` — неполное или неоднозначное свидетельство, не блокирующее упаковку.

## Запуск

```powershell
npm run audit:project
npm run audit:project:json
npm run check
npm test
npm run test:ui
```

Инструмент `audit_project` доступен модели для чтения исходников, прикреплённых к текущему чату. Он не получает произвольный доступ к файловой системе компьютера или к другим чатам.

## Ограничения и безопасность

- Анализ статический: исполняемый код не запускается.
- Аудитор не исправляет файлы и не удаляет данные.
- CLI исключает сторонние зависимости, локальные базы, runtime-данные, артефакты и `public/vendor`.
- Проверяются только распознанные текстовые исходники; бинарные файлы, изображения и недоступные фрагменты не анализируются.
- Лимиты: до 1 000 файлов и 8 МБ исходного текста на один проход.
- Эвристики допускают ложные срабатывания. Например, легитимное использование `innerHTML` после санитизации или тестовые фиктивные ключи требуют ручного контекста.
- Отсутствие находок не доказывает отсутствие уязвимостей или ошибок. Для полной оценки нужны тесты, проверка зависимостей, runtime-проверки и ручной review.

## Проверка текущей рабочей копии

Контрольный проход охватил 381 файл исходного кода. После уточнения сигнатур запуска процессов получено 185 замечаний уровня review и 7 информационных сигналов; находок уровней high/error не зарегистрировано. Регрессионные тесты аудитора: 7/7 пройдено. Эти цифры описывают эвристический прогон, а не подтверждение безопасности проекта. Исходники при аудите не исполнялись.
