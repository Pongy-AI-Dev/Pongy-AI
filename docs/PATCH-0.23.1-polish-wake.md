# Pongy AI 0.23.1 — переключатель разделов, Plus и запуск голосового триггера

## Установка

Распаковать ZIP **в корень полного проекта поверх всех предыдущих патчей**, включая `Pongy-AI-0.23.1-ci-persistence-fix.zip`, с заменой одноимённых файлов. Это не полный проект. Старые документы в `docs` не удалять. `.env`, рабочую БД, аккаунты и установщики не заменять. Перезапустить сервер и принудительно обновить страницу, чтобы браузер получил новые CSS и JS.

Версия остаётся 0.23.1. Зависимости, серверная авторизация, настройки CORS, workflow CI и нативные сборки не меняются. Новых установщиков MSI/APK в этом ZIP нет.

## Интерфейс

- Убран псевдоэлемент блика у ползунка «Чаты / Заметки». Раньше после завершения анимации его прозрачность оставалась равной 1, а трансформация возвращалась в исходное положение. Это оставляло плоскую полосу на выбранном разделе. Плавающий индикатор и переключение разделов сохранены; декоративная полоса отключена также при reduced motion.
- Обе кнопки Plus используют одинаковый более заметный мягкий градиент, зависящий от выбранного цвета интерфейса. Звёздочка акцентная, текст контрастный, есть состояние наведения и видимый клавиатурный фокус.
- Проверены шесть акцентов в светлой и тёмной темах: контраст текста Plus не ниже 4.5:1 на остановках градиента и его состоянии наведения. Макеты просмотрены при 1440×1000 и 390×844.

## Голосовой триггер

Исправлен **запуск и жизненный цикл** существующего локального распознавателя, а не заменён его акустический движок:

1. `getUserMedia` теперь получает `{ audio: { ... }, video: false }`. Ранее аудиопараметры передавались на верхнем уровне; первичный запрос был некорректен, а резервный терял настройки шумоподавления и монофонического ввода.
2. Аудиоконтекст создаётся/разблокируется синхронно при включении переключателя, **до** асинхронной загрузки модели. На последующем касании страницы возобновляется тот же контекст, а не новый контекст из отложенного таймера, снова заблокированный autoplay-политикой.
3. Блокировка запуска звука не выдаётся за отказ в разрешении микрофона. Для неё сохраняется контекст и предлагается коснуться страницы. Настоящий отказ в разрешении микрофона по-прежнему требует разрешения пользователя.
4. Watchdog восстанавливает поток после приостановки аудиоконтекста браузером. При завершении аудиодорожки запускается повторная попытка. Слушание не должно молча застревать после остановки аудио.
5. При смене языка интерфейса старые распознаватель и микрофон освобождаются, затем запускается модель нового языка. Для русского зова используется русский язык интерфейса.
6. Известное приблизительное начало «он ге»/«о ге» может подтверждаться без финального события Vosk, но только после стабильного частичного результата (не менее 1.2 секунды) и измеренной тишины (не менее 0.8 секунды). Продолжение посторонней фразы отменяет кандидата. Проверка начала фразы и ограничения на неоднозначные команды сохранены; принудительной узкой грамматики бренда нет.
7. Между голосовыми командами сохраняется уже разблокированный аудиоконтекст, но дорожки микрофона фонового слушателя освобождаются. Это позволяет вернуть триггер после команды без создания нового заблокированного контекста.
8. При выключении переключателя освобождаются дорожки микрофона и аудиоконтекст. Обычная подсказка остаётся короткой: «Позовите Pongy».

Для диагностики из консоли браузера доступно `PongyWakeWord.diagnostics()`: состояние потока, язык, состояние аудиоконтекста, наличие живой дорожки, блокировка разрешения и последняя распознанная строка. Строка хранится только в памяти текущей страницы, не отправляется в аналитику и не сохраняется в БД. Это не запись звука.

### Ограничения и ручная проверка

Нужны HTTPS (либо localhost), доступ к микрофону, загрузившаяся локальная модель и включённый переключатель. При сообщении об ожидании звука коснуться страницы. При отказе доступа разрешить микрофон средствами браузера и включить переключатель заново.

Точное распознавание живого произношения «Понги» не гарантируется: оно зависит от словаря Vosk, произношения, микрофона и шума. В этой среде нет микрофона пользователя; автоматические проверки триггера используют подставные результаты Vosk. Отдельная проверка `speech-ui.cjs` обрабатывает настоящую русскую аудиозапись с числами, но это **не** проверка произнесённого имени «Понги». После установки необходим ручной тест с реальным голосом. Качество уровня «Алисы» этим патчем не заявляется.

Распознавание имени выполняется локально. Для последующей команды сохраняется речевой сервис браузера с офлайн-резервом; сервис браузера может передавать звук своему провайдеру. Обычный сайт не может принудительно поднять вкладку поверх окон ОС. Существующий нативный мост может активировать окно приложения; сайт в фоне подаёт сигнал и принимает команду при возвращении пользователя. Лимит команды после 10 секунд тишины сохранён.

## Проверки

- `tests/wake-runtime.test.js`: десять проверок аудиопараметров, разблокировки до загрузки модели, повторного жеста, отказа autoplay/микрофона, смены языка, тихого подтверждения, восстановления приостановленного контекста и освобождения микрофона, а также повторного запуска после команды.
- `tests/wake-word-ui.cjs`: настоящий аудиопоток Chromium с искусственным микрофоном и подставными результатами распознавания; дополнены проверки первого запроса микрофона, смены языка и выключения.
- `tests/update-0231-ui.cjs`: отсутствие блика в покое/после переключения/reduced motion/на телефоне, градиент и контраст всех акцентов, одинаковые кнопки Plus и прежние UI-регрессии.
- В `tests/voice-scroll-ui.cjs` движение точки теперь ожидается в пределах цикла анимации: два снимка с интервалом 420 мс могли оба попадать в неподвижную часть и давать ложное падение. Требование фактического изменения transform сохранено; отключённая или замороженная анимация тест не пройдёт.
- Полный набор модульных тестов и существующий набор браузерных тестов запускаются без отключения сценариев. Локально доступен Chromium; Firefox и WebKit нужно подтвердить существующей матрицей GitHub Actions.
