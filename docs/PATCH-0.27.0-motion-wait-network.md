# Исправление гонки ожидания и ложного офлайн-режима — 0.27.0

Небольшой исходный патч **поверх `Pongy-AI-0.27.0-network-response-recovery.zip`**. Это не полный проект, не установщик и не изменение домена.

## WebKit / motion-ui.cjs

Причина `wrong localized waiting label`: тест дожидался только появления `.thinking`, а затем немедленно требовал «Размышляю». Однако перед генерацией правильными этапами являются «Подготавливаю запрос» и «Подключаюсь к модели». Видимость индикатора не означает готовность нужного этапа.

Тест теперь ограниченно ждёт **именно этап «Размышляю»**, после чего выполняет прежнюю точную проверку русского текста. Проверки реального движения анимаций, пикселей, сохранения DOM, доступности, reduced motion, мобильного интерфейса и безопасности HTML не удалены. В fixture добавлена небольшая задержка запроса (по умолчанию 250 мс; параметр `PONGY_MOTION_REQUEST_DELAY_MS`, предел 2500 мс), чтобы ранние этапы действительно проверялись, а гонка не скрывалась за скоростью локального сервера.

## Сайт / Service Worker

Worker больше не показывает публичный офлайн-экран только на основании `navigator.onLine === false`. Этот флаг — сигнал браузера/ОС, а не доказательство недоступности Pongy. Теперь сначала выполняется один ограниченный сетевой GET навигации; при фактической ошибке, таймауте или HTTP 5xx остаётся прежний публичный экран восстановления. Это устраняет приложение-зависимый случай: сервер доступен, но ложный offline-флаг удерживает посетителя в заглушке.

Не добавлены повторы сообщений, платежей или других POST-запросов. API, аутентификация, скачивания, приватная история и ключи не помещаются в кеш. Предел ожидания 120 секунд сохранён. Кеш общедоступной заглушки имеет новую ревизию `recovery2`.

**Если соединение сбрасывается до TLS/HTTP, этот патч не создаёт сетевой маршрут к Render.** Ошибки `ERR_CONNECTION_RESET`/SSL timeout требуют отдельной диагностики конкретной сети и точки входа. Работоспособность из одной сети не доказывает доступность из России или у другого провайдера. Домен, DNS, сертификат, CSP и проверка HTTPS не изменены.

## Проверено фактически

- Исходная база восстановлена по полному MANIFEST: совпали все файлы последнего патча.
- На старом тесте воспроизведено: без задержки Chromium проходит; при задержке 300 мс возникает та же `wrong localized waiting label`.
- Исправленный `motion-ui.cjs`: **29 проверок** при задержках **0, 300 и 1800 мс**, все три запуска прошли в Chromium.
- `motion-ci.test.js`, `offline-worker.test.js`, `startup.test.js`, `service-warnings.test.js`, `reliability.test.js`: **27/27**, включая доступный сервер при ложном offline-флаге, настоящий сетевой отказ и запрет кеширования приватных данных.
- `notifications-offline-ui.cjs`: **30 проверок**, включая настоящий офлайн и публичную заглушку.
- `startup-ui.cjs`: **15 проверок**, включая поздний запуск, сохранность данных и ограниченные попытки.
- Синтаксис, структура проекта и полный MANIFEST проверяются командой `npm run check:release`; ZIP сверяется как точное наложение на предыдущий архив.

WebKit/Firefox локально не установлены и в этом запуске не проверялись. Полный набор из 61 UI-suite и полный npm test заново не запускались: выполнены перечисленные целевые проверки. Ваш журнал GitHub подтверждает 60/61 WebKit-наборов до этого исправления, но следующий workflow должен отдельно подтвердить исправленный сценарий.

Во время диагностики из среды агента `/`, `/healthz`, `/api/config`, `app.js` и `app.css` получены с HTTP 200 и обычной проверкой HTTPS. Тело публичного `app.js` совпало по SHA-256 с предыдущим выданным патчем. Это наблюдение **только из сети агента**, не проверка соединения пользователя. Изменения на Render/DNS не выполнялись.

## Применение

1. Сохраните резервную копию исходников. Распакуйте ZIP в корень проекта после network-response-recovery с заменой одноимённых файлов.
2. Запустите новый GitHub workflow. Старый упавший журнал не изменится.
3. Для изменения поведения сайта разверните публичный `reminder-sw.js` и остальные файлы обычным deploy. Затем перезагрузите сайт, чтобы новый worker обновился. Не очищайте cookies, IndexedDB, историю, API-ключи и настройки.
4. Если без VPN остаётся ошибка браузера до загрузки страницы, нужна отдельная проверка сети/хостинга; повторная публикация JavaScript сама по себе не исправляет TLS timeout.

В архиве нет готовых Windows/Android пакетов; для этих изменений пересборка нативной оболочки не требуется, поскольку она загружает сайт.
