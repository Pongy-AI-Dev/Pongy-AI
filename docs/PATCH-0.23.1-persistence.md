# Сохранение настроек и уведомлений — hotfix 0.23.1

## Установка

Распаковать ZIP в корень **полного проекта**, поверх всех предыдущих патчей 0.23.1, включая исправления CI, Actions Node 24 и прокрутки настроек. Заменить одноимённые файлы. Старые документы в `docs`, `.env`, базу данных и остальные файлы удалять не нужно.

**Перезапустить сервер**, затем принудительно обновить страницу. В этом патче есть серверное исправление: одной замены клиентских файлов недостаточно. Установка новых npm-зависимостей не требуется. Версия приложения остаётся 0.23.1; workflow и нативные установщики не меняются.

Если настройка уже была потеряна до исправления и её нет в локальной копии, выбрать её заново один раз. Патч не может восстановить ранее удалённые данные из ничего.

## Причины и исправления

### Настройки и галочки

- Серверный обработчик `/api/preferences` не включал `motion` в сохраняемую запись. Поэтому режим анимаций оставался только на устройстве, а новый браузер или более свежая серверная запись могли его сбросить. Теперь режим сохраняется и сохраняется при частичном обновлении других настроек; некорректное значение не стирает предыдущий корректный выбор.
- Выход из аккаунта очищал таймер отправки настроек, не дождавшись последней записи. Теперь сначала дожидаемся сохранения. При ошибке серверной записи выход не выдаётся за успешный: локальная очередь остаётся, а ошибка отображается в строке состояния. После восстановления сети запись повторяется.
- Операция `flushPreferences` теперь возвращает реальный результат записи, а не уже обработанную и подавленную ошибку. Фоновые вызовы обрабатывают отклонение явно; ожидающий сохранения код получает ошибку.
- Добавлена резервная очередь в памяти на случай отказа записи в localStorage. Это позволяет отправить текущие изменения серверу, но не заменяет постоянное хранилище при закрытии браузера.
- После загрузки настроек заново синхронизируются галочки памяти, бета-функций, видимость бета-раздела и выбранный голос. Это важно при позднем ответе сервера и переключении аккаунтов, когда панель уже была построена со значениями по умолчанию.
- При уходе страницы в фон дополнительно запускается отправка очереди. Если документ закроется раньше завершения запроса, локальная очередь не удаляется без подтверждения и повторяется после следующего входа/восстановления сети.

### Уведомления

- История зеркалируется на устройстве отдельно для каждого аккаунта, максимум 200 последних записей. Пустой или неполный ответ сервера больше не затирает уже известную историю: в приложении нет отдельной команды удаления этих уведомлений.
- Локальная копия больше не удаляется автоматически через 14 дней. Серверная история продолжает храниться в БД; локальная копия дополняет её, а не служит общедоступным кешем API.
- Сортировка «по возрастанию», «по убыванию» и «сначала важные» сохраняется вместе с историей аккаунта.
- Чтение уведомления немедленно отражается локально. ID для отметки прочтения сохраняются в отдельную очередь; при ошибке сети очередь остаётся и повторяется при опросе, восстановлении сети или возвращении в окно. Успешный ответ удаляет только подтверждённые ID.
- Уже прочитанное уведомление не становится снова непрочитанным из-за устаревшего серверного снимка. Очереди и история разных аккаунтов не смешиваются.

## Что проверяется

Новый сценарий `tests/preferences-persistence-ui.cjs` проверяет запись режима анимаций на сервер, восстановление переключателей после перезагрузки и в новом браузере, позднюю загрузку настроек, включение/выключение уведомлений, быстрый выход после изменения, сортировку, чтение без сети и повторную отправку, пустой серверный снимок, отказ записи настроек с кодом 503, повторную загрузку с несохранёнными изменениями, а также смену аккаунта в том же браузере.

Дополнительный серверный тест в `tests/preferences.test.js` закрывает и снова открывает приложение с тем же `DATA_DIR`: настройки, история уведомлений и серверная отметка прочтения должны сохраниться. Тестируются также частичные изменения и явное выключение галочек.

В старом тесте офлайн-уведомлений сохранена проверка реальной записи прочтения в БД. Теперь перед ней ожидается ответ `POST /api/notifications/read`, поскольку исчезновение локальной точки уже не означает завершение сетевого запроса.

## Границы сохранения

Настройки аккаунта сохраняются через прежнее серверное хранилище (SQLite либо настроенный Firestore). Мобильный режим, крупные значки, цвет, всплывающие уведомления и включение голосового ожидания остаются настройками **устройства**: внешний вид телефона не должен автоматически менять компьютер. Они сохраняются локально, как и прежде.

Для долговременной **серверной** истории уведомлений нужен постоянный диск для `DATA_DIR` и файл БД. Если хостинг удаляет БД при redeploy или запускает несколько экземпляров с разными БД, код патча не создаёт общий постоянный диск. Локальное зеркало защищает уже полученную историю на этом устройстве, но не гарантирует появление удалённых серверных данных на новом устройстве.

Локальная проверка выполнялась в Chromium на Linux. Успешный прогон Firefox/WebKit здесь не заявляется: их проверяет существующая матрица GitHub Actions.
