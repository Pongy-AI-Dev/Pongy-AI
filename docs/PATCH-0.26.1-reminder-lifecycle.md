# Pongy AI 0.26.1 — жизненный цикл опроса напоминаний

## Применение

Дополнительный ZIP поверх полного проекта 0.26.1 со встроенным скачиванием и предыдущим **extension-ci-hotfix**. Распакуйте в корень с заменой одноимённых файлов; старые docs, `.env`, базы и загрузки не удалять. Обновите фронтенд и сервер Render, перезагрузите страницу. Новых зависимостей npm, настроек CORS, cookie, OAuth или секретов нет. Установщики и расширение не пересобраны; предыдущий выбор полного Chromium для CI сохранён. Номер остаётся 0.26.1: точечное исправление существующего выпуска. app.js отдаётся no-store; reminders.js получает новый ETag, поэтому старое тело не должно сохраняться после обновления страницы.

## Проблема и предел вывода из лога

В присланном WebKit-прогоне 48/49 UI-наборов завершились успешно. session-ui.cjs завершил сценарий сессии, но обнаружил накопленный pageerror `/api/reminders due to access control checks`. Одна эта строка не доказывает ошибку серверного CORS и не сообщает, на какой перезагрузке она возникла.

В коде найден конкретный дефект: pending GET напоминаний не отменялся до pagehide, при скрытии или reset, а общий api() заменял AbortSignal вызывающего кода собственным таймерным контроллером. При сбросе не было номера поколения запроса; поздний ответ того же аккаунта мог пересечься с новым входом, старый finally — сбросить занятость нового опроса. Новый тест на предыдущей версии обнаруживает отсутствие отмены при навигации. Это исправление найденной гонки, не заявление об успешном локальном воспроизведении всех особенностей WebKit.

## Что изменено

- При pending-опросе временно установлен beforeunload-обработчик ранней отмены. Он не вызывает preventDefault и не показывает диалог; после завершения/отмены удаляется, чтобы не оставлять постоянное препятствие bfcache. Если навигация отменена другим кодом, опрос не остаётся заблокированным. На реальной перезагрузке одного pagehide оказалось недостаточно: браузер мог завершить fetch раньше. Новый тест проверяет раннюю отмену.
- Только опрос GET `/api/reminders` получает собственный AbortController. `reset` и смена видимости отменяют текущий опрос; `pagehide` также блокирует новые опросы до `pageshow`. Сохранение, перенос, удаление и подтверждение напоминания этим контроллером не прерываются.
- Фоновая открытая вкладка по-прежнему может выполнять периодический опрос каждые 15 секунд; он не отключён навсегда при document.hidden. Восстановление видимости/страницы запускает новый опрос только при подтверждённой готовности сессии. Web Push и серверный планировщик не изменены.
- Ответы и finally проверяют поколение. Старый ответ не перезаписывает данные нового запроса даже после reset и повторного входа тем же аккаунтом.
- `api()` передаёт отмену вызывающего кода внутреннему fetch-контроллеру, удаляет подписку после завершения и не отправляет fetch с уже отменённым сигналом. Тайм-аут 35 секунд сохранён. Отмена классифицируется как AbortError, а не NETWORK_ERROR; реальные сетевые ошибки, HTTP-ошибки и истечение сессии не скрываются. После отмены старый 401 не может инвалидировать текущую сессию.
- Тест session-ui.cjs не фильтрует ошибки CORS и не отключён. Добавлен отдельный кросс-браузерный UI-набор с удержанным запросом, реальными перезагрузками и восстановлением опроса. Он включён в общий runner.

## Проверки

- Полный `npm test` на проекте, восстановленном наложением ZIP на предыдущий extension-ci-hotfix: **655/655**, без пропусков и ошибок. Из них 11 новых unit-тестов проверяют жизненный цикл опроса и передачу отмены в api().
- Целевой регрессионный прогон Chromium в CI-режиме: **7/7 запусков**. Новый reminder-lifecycle-ui.cjs — дважды по 11 проверок; session-ui.cjs — дважды по 39; reminder-flow-ui.cjs — 52; mobile-reminders-ui.cjs — 41; preferences-persistence-ui.cjs — 25. Это пять выбранных наборов, а не полный прогон всех 50 UI-наборов.
- Новый UI-тест на предыдущем коде завершается ошибкой отсутствия отмены запроса при навигации; на исправленном коде проходит. Накопленные pageerror не фильтруются.
- `npm run check:release` проходит; наложение ZIP проверяет побайтовое совпадение всех 380 исходных файлов, без удаления старых файлов. В архиве только 11 изменённых/новых файлов, включая MANIFEST.sha256 и документацию.

WebKit скачан, но локальный Amazon Linux не содержит его GTK/GStreamer/ICU и других требуемых библиотек. Локальный запуск WebKit не заявляется; проверку именно WebKit необходимо повторить в Ubuntu GitHub Actions. Chromium проверяет реальную отмену HTTP-запроса при навигации и функциональные сценарии; unit-тесты проверяют поздние ответы и отмену на уровне Promise/AbortSignal. Это не гарантия устранения любых иных причин CORS-ошибок.
