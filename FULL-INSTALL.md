# Полная версия Pongy AI 0.6.7

Это полный проект, не частичный патч. Предыдущие ZIP последовательно устанавливать не нужно.

## Обновление через сайт GitHub

1. Сохраните копию текущего репозитория. Отдельно сохраните реальные данные базы, если храните их на постоянном диске. Экспортируйте локальную историю из настроек Pongy AI.
2. Распакуйте архив. Внутри находятся server.js, package.json и папки public, lib, tests, .github.
3. Загрузите содержимое архива в корень существующего репозитория с сохранением папок и заменой совпадающих файлов. Не загружайте ZIP как файл и не создавайте лишнюю внешнюю папку проекта. По возможности опубликуйте всё одним коммитом, а не файл за файлом.
4. В репозитории удалите старый дубликат `env.example` без начальной точки и случайный файл `download`, если они остались. Оставьте `.env.example` — это шаблон, не реальные секреты.
5. Убедитесь, что `.github/workflows/checks.yml`, `tests/browser.cjs`, `tests/browser.test.js`, `tests/fixtures/text.pdf` и `tests/fixtures/text.docx` находятся по этим путям. Скрытые файлы .github, .gitignore, .gitattributes и .env.example тоже входят в архив.
6. Откройте Actions → Checks и смотрите запуск именно для последнего коммита. Старые красные запуски не меняют свой результат. Промежуточный коммит с половиной файлов может закономерно не пройти тесты.
7. В Render оставьте текущий сервис, все Environment-переменные, JWT_SECRET, SESSION_SECRET и данные без изменений. Команда сборки: `npm ci`; запуск: `npm start`. Выполните Manual Deploy → Deploy latest commit, если автодеплой не произошёл.
8. После успешного Live обновите сайт с очисткой кеша и проверьте версию 0.6.7 в подвале.

**Не удаляйте реальные .env, data/, базу и резервные копии на рабочем сервере. Не загружайте их в GitHub.** В полном архиве их нет намеренно. Если .env или реальные секреты уже попадали в GitHub, уберите их из репозитория и замените раскрытые секреты; один .gitignore не удаляет уже опубликованное из истории Git.

Новые переменные для этого обновления не требуются. Если у вас COOKIE_SAMESITE=none, не заменяйте его на значение из шаблона. Для none требуется HTTPS и Secure cookie. Render сам по себе не сохраняет временный диск навсегда: используйте локальные JSON-копии, постоянный диск или отдельно настроенный Firestore.

## Чистая локальная установка

Требуется Node.js 22 или новее; CI использует Node.js 22.

1. Установите зависимости командой `npm ci`.
2. При необходимости скопируйте .env.example в .env и заполните значения. Без ключа ИИ приложение откроется, но ответы ИИ будут недоступны. Google, Firebase, поиск и почта требуют своих настроек.
3. Запустите `npm start` и откройте http://localhost:3000.

## Проверки

- `npm run check` — синтаксис.
- `npm test` — автоматические тесты с локальными фикстурами, без ваших реальных ключей.
- `node node_modules/playwright/cli.js install --with-deps chromium` — браузер и библиотеки для поддерживаемого Linux/CI.
- `BROWSER_ENGINE=chromium npm run test:ui` — Chromium; аналогично firefox и webkit после установки соответствующего движка. Это синтаксис Linux/macOS; для PowerShell задайте `$env:BROWSER_ENGINE='chromium'`, затем `npm run test:ui`.

Браузеры нужны для тестов, а не для обычного запуска сайта на Render. В GitHub Actions они устанавливаются автоматически. Удалять тесты или выставлять фиктивный CHROMIUM_PATH не нужно.

## Ограничения

Оплата остаётся заглушкой. Реальный Google OAuth, письма Firebase, поиск и модели зависят от ваших настроек и внешних сервисов. Прохождение тестов с фикстурами не заменяет проверку реального входа и ответов провайдера. Локальная история не гарантируется «навсегда» и не содержит бинарные файлы в JSON-копии.
